Add a new top-level navigation item called RESOURCES to the website.

The Resources section should not be a generic blog only. It should be a structured knowledge, education, and enablement hub for different audiences using the platform.

Goal:
Help visitors and users understand the product, workflows, integrations, AI/LLM setup, CMS integrations, file support, system credits, routing logic, and best practices based on their role and use case.

Important:
The content of the Resources hub must be manageable through the System Admin Panel.
Do not hardcode all content only in frontend code.
Admins must be able to create, edit, organize, publish, unpublish, and expand resource content without needing code changes.

Also important:
Do not treat this as a UI-only website feature.
This must be a real CMS-backed, admin-managed, operational Resources system with working data models, admin CRUD, frontend rendering, search/filter logic, and real runtime behavior.

7. HOW SYSTEM CREDITS WORK
==================================================

Create a dedicated resource page or guide explaining system credits.

This page should clearly explain:
- what credits are

- difference between platform credits and BYOK

8. HOW THE SYSTEM DECIDES WHICH LLM TO USE
==================================================

Create a dedicated resource page that explains how the system selects the right LLM for specific content.

This page should clearly explain that model selection may depend on factors such as:
- source language
- target language
- language pair
- subject matter/domain
- content type
- long document vs short document
- table-heavy vs plain text
- low-resource language
- customer plan / workspace settings
- quality vs speed vs cost preference
- BYOK availability
- admin routing rules
- provider/model health and fallback status
- required features such as JSON mode, long context, glossary handling, terminology control, or style guidance

Explain possible routing examples like:
- legal and technical content -> higher reasoning / terminology-focused models
- marketing and creative content -> models better at tone and nuance
- long reports / books -> long-context models
- Arabic / CJK / low-resource languages -> routing based on configured strengths and approved models
- if primary model is unavailable -> fallback chain applies

Important:
Do not present this as marketing-only copy.
It should reflect real routing logic supported by the platform.
