We are repositioning our platform from a "localization/translation" platform to a 
"multilingual content creation" platform. This requires a terminology rebrand across 
the entire codebase — UI labels, copy, page titles, navigation items, and descriptions. 
This is a UI/copy change only. Do NOT rename database columns, Prisma model fields, 
API route paths, or any backend identifiers — those must stay as-is to avoid breaking 
changes.

---

## TERMINOLOGY REPLACEMENTS

Apply these find-and-replace rules across all UI-facing text (component JSX, page 
titles, labels, descriptions, button text, toast messages, empty states, onboarding

  LinguistProfile, TranslationMemory, TMEntry, GlossaryTerm)
- All API route paths (e.g., /api/studio/jobs, /api/linguist/*, 
  /api/tm, /api/glossary)

  in the CAT editor panels, TM match percentage UI, or TMX file import/export

- "BYOK" — keep as-is
- Any enum values in the codebase (e.g., TRANSLATOR, REVIEWER role enums) 
  — only change the display labels, not the underlying values
- Route URLs and slugs

## APPROACH

1. Start with the sidebar and navigation — highest visibility.
2. Then workflow type selectors in the job creation flow — most strategically 
   important rename (Human Translation → Native Creation).
3. Then the Linguists/Strategists tab and sub-tabs.
4. Then Creator Studio (formerly Linguist Studio).
5. Then Brand Assets page.
6. Then admin panel copy.
7. Finally sweep remaining files for any missed instances of "linguist", 
   "translator", "localization" in UI-facing strings.

After completing, do a final search across all .tsx files for the strings: 
"linguist", "translator", "localization", "translation" and flag any remaining 
instances that appear in user-facing text for review.
